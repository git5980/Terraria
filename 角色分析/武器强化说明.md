# 武器/装备强化：只改「我手里这一把」

> 配套脚本：`weapon_ops.js`（默认只读）。目标：**判断当前选中的武器 → 只强化这一个物品实例**；
> 同类型的其它副本、以及以后打造/购买/掉落的同款武器，**一律保持原厂数值**。

---

## 一、原理：为什么天然「只对这一把生效」

泰拉瑞亚的物品属性（伤害/暴击/使用时间/弹速…）**存在 `Terraria.Item` 实例上，不在物品类型上**。

- 背包每个格子是一个**独立的 Item 对象**：`Player.inventory[i]`；
- 改 `inventory[选中格]` 那个对象的字段 → 只影响这一格；
- 以后打造出的同款武器是**新对象**，由 `Item.SetDefaults(type)` 生成，拿到的是原厂数值。

所以这不是「绕过限制」，而是**按游戏本来的数据结构操作**：物品类型（type）没变，变的是这一个实例。

---

## 二、怎么认出「当前选中的武器」（实测踩坑记录）

| 候选 | 结果 |
|---|---|
| `Player.selectedItem` 字段 | ❌ **本移植版不存在**（是属性，不是字段） |
| `Player.get_selectedItem()` 属性 | ⚠️ 返回值不可靠（不是直接的索引或 Item 引用） |
| `Player.selectedItemState` 结构体 | ⚠️ 是嵌套类型，直接按偏移读会读到垃圾 |
| **`Player.lastHotbarItem`（int）** | ✅ **可用**：当前选中的热键栏序号 → `inventory[lastHotbarItem]` |
| `Player.get_LocalPlayer()` | ⚠️ 在脚本线程调用**会抛托管异常**，所以脚本改用「扫 `active==true`」定位玩家 |

脚本每次都会打印**整条热键栏并给命中格打 ★**，你可以直接核对是不是手里那把；
如果判断错了，把 `CONFIG.target` 改成 `"slot"` 并手动写 `slot: N`。

## 三、怎么用

1. 起脚本下发服务（容器里，保持后台）：
   ```bash
   cd "/sdcard/Download/DSHA/泰拉瑞亚项目/角色分析" && nohup python3 -m http.server 8791 --bind 127.0.0.1 &
   ```
2. 改 `weapon_ops.js` 顶部：
   ```js
   enabled: true,          // 先 false 跑一遍确认★选中格，再改 true
   target: "selected",     // 或 "slot"
   mods: {
     damageAdd: 100,       // 伤害 +100
     damageMul: 1,         // 再乘倍率（1 = 不乘）
     crit: 100,            // 暴击 100%
     useTime: 8,           // 使用时间 8 帧（越小越快）
     autoReuse: true       // 自动挥舞
   }
   ```
3. 在 JsHook 里执行 `http_eval.js` 的内容（拉最新脚本进游戏进程执行）。

**游戏里切换武器后重新运行**，就会作用到你新选中的那把。

## 四、可改字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `damage` | int | 伤害（用 `damageAdd` / `damageMul` 换算，带 `maxDamage` 上限保护） |
| `crit` | int | 暴击率 %（原版基础 4） |
| `useTime` / `useAnimation` | int | 使用时间 / 动画帧（越小挥得越快） |
| `knockBack` | float | 击退 |
| `shootSpeed` | float | 弹速 |
| `autoReuse` | bool | 自动挥舞 |
| `rare` | int | 稀有度颜色（0 白 1 蓝 … 10 红） |
| `value` | int | 售价（铜币） |
| `scale` | float | 外观缩放 |
| `mana` | int | 魔力消耗 |

也可用 `WEAPON.set("damage", 999)` 单独改一项（同一次脚本会话内有效）。

## 五、实测证据（2026-09-17，角色「偶泥考」槽位0 铜短剑）

| 步骤 | 结果 |
|---|---|
| 识别选中武器 | `lastHotbarItem=0` → `inventory[0]` = **铜短剑(type 3507)**，热键栏 0-9 全部列出核对 ✅ |
| 修改前 | 伤害=5 击退=4 暴击=5% 使用时间=13 弹幕=938 弹速=2.1 稀有度=1 售价=423 缩放=0.8 前缀=61 |
| **+100 伤害** | 伤害 **5 → 105**，其余字段不变 ✅ |
| **新造一把同款**（模拟以后打造/掉落） | `{damage:5, crit:0, useTime:13, rare:0, prefix:0}` → **仍是原厂数值** ✅ |
| 恢复 | 按会话快照精确还原 → 伤害回到 **5**，所有字段与原值一致 ✅ |
| 无快照时的恢复路径 | `Item.SetDefaults(type,false)` + 重挂前缀 → 同样回到 5 ✅ |

> 顺带观察：这把铜短剑带有**国服自研前缀 61**，并带弹幕 938 / 缩放 0.8 —— 说明国服版本有专属词缀系统，
> 直接改实例的最终数值可以叠加在词缀效果之上。

---

## 六、恢复方式

- **本次会话内**：`WEAPON.restore(WEAPON.origin)` → 逐字段还原（最精确）。
- **新开脚本**：把 `CONFIG.revert` 改成 `true` → 走 `Item.SetDefaults(type,false)` 回原厂，并自动把原前缀挂回。
- 想彻底复原：读档（改完没保存的话）；已保存的话重新打造一把即可。

---

## 七、注意事项

1. **只改你选中的那一格**；同名武器在别的格子不会被改（脚本会打印同类型副本对比）。
2. **以后打造/掉落/购买的同类武器是原值**——这是本方案的核心特性，不是副作用。
3. **别对着方块/材料改**：默认 `onlyWeapons: true`，`damage<=0` 的物品会跳过（会提示）。
4. **前缀参与计算**：脚本直接写最终数值，所以是「在原词缀基础上再强化」；重挂前缀时数值可能微调（已知现象）。
5. **保存时机**：物品实例的改动要等游戏自动存档/退出保存才落盘；改完想保留就别急着退。
6. **联机**：本地改动可能被服务器同步覆盖，建议单机使用。
7. 伤害有 `maxDamage`（默认 99999）上限保护，防止写爆导致异常。
8. 脚本默认 `enabled=false`，**不会自动改任何东西**。
