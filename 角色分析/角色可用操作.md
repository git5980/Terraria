# 泰拉瑞亚角色可用操作清单（通用版）

> **不绑定任何角色。** 无论现在这个存档角色、还是以后新建的角色，都能定位并修改。
> 配套文件：`player_ops.js`（执行脚本）、`profiles.json`（配置模板）、`buff_ids.json`（增益 ID 表）。

---

## 〇、怎么用（三步）

1. **起脚本下发服务**（容器里，保持后台运行）：
   ```bash
   cd "/sdcard/Download/DSHA/泰拉瑞亚项目/角色分析" && nohup python3 -m http.server 8791 --bind 127.0.0.1 &
   ```
2. **在 `player_ops.js` 顶部改三行**：
   ```js
   enabled: false,        // 先保持 false 跑一遍看属性，确认无误再改 true
   target:  "local",      // 改哪个角色，见第一节
   profile: "满配角色",     // 套哪套模板，见第二节；留空则只用内联配置
   ```
3. **在 JsHook 里执行 `http_eval.js` 的内容**（它会把最新的 `player_ops.js` 拉进游戏进程执行）。

## 一、通用目标选择 `CONFIG.target`

| 写法 | 含义 | 适用 |
|---|---|---|
| `"local"` | **当前本地玩家**（默认） | 单机、联机都对；新建角色也能直接命中 |
| `"all"` | 本局所有**活跃**角色 | 联机时对所有人；单机就是自己 |
| `"name:偶泥考"` | 按角色名精确匹配（找不到自动退回包含匹配） | 多角色/多存档时点名 |
| `"slot:0"` | 按玩家槽位（`Main.player[256]` 的下标） | 精确到对象，调试用 |

脚本每次运行都会先**扫描**并打印，确认选对了再动手：

```
=== 角色扫描（player 数组长度 256，检出 1 个）===
  ★ 槽位#0 whoAmI=0 名字=偶泥考 生命=100/100 魔力=20 防御=0 难度=1 活跃=是  ← 本地玩家
[*] 目标选择 "all" → 命中 1 个角色：#0 偶泥考
```

**本地玩家是怎么认出来的（不靠槽位 0、不靠角色名）**：
1. 先调 `Main.get_LocalPlayer()` **属性**（这是 `Terraria.Main` 里的属性，不是字段，按字段名查是找不到的）；
2. 失败再调 `Main.get_myPlayer()` 取索引 → `player[索引]`；
3. 再失败才退回「第一个 `active==true` 的角色」。

> 实测：本机单机时 `activePlayerCount = 1`，槽位 #0 就是本地玩家；但上面这条链在联机、切换角色、新建角色后都成立，**所以脚本不写死任何槽位或名字**。

**新角色场景**：新建角色进入世界后，它的对象同样出现在 `Main.player[]` 里，`get_LocalPlayer()` 立即指向它；直接改 `target` 就能对它生效——不需要改脚本、不需要知道名字（用 `"local"` 即可）。

## 二、配置模板 `profiles.json`

改数据不用改代码：模板放在 `profiles.json`（脚本运行时通过 HTTP 拉取），`CONFIG.profile` 写模板名即可。

| 模板 | 效果 |
|---|---|
| `无` | 空模板（只做扫描/回读） |
| `快速起步` | 生命 200 / 魔力 100（持久） |
| `满配角色` | 生命 500 / 魔力 200 / 呼吸 400（持久）+ 防御 100、四类伤害 ×3、暴击 100、移速 1.8、跑速 9、跳跃 4、翅膀 200、幸运 1、减伤 0.5（持续） |
| `上帝模式` | 防御 200、减伤 0.5、无敌帧 3600、受击闪避、抗岩浆、抗微光（持续）+ 回满血（动作） |
| `飞毛腿` | 移速 1.6、跑速 12、加速跑 9、跳跃 5、自动跳跃 |
| `工匠快采` | 镐速/物块放置/墙放置 ×5、移速 1.4 |
| `幸运拉满` | 幸运 1 |
| `经典难度` / `旅途难度` | `difficulty` 改 0 / 3（持久） |
| `回满血` / `清减益` | 一次性动作 |
| `强力增益包` | 一次性加 11 个常用增益（黑曜石皮肤、回血、迅捷、铁皮、魔力再生、魔法之力、洞穴探险、夜猫子、战斗、箭术、猎人）各 10 分钟 |

自定义模板：在 `profiles.json` 的 `profiles` 里加一项即可（字段名与 `角色状态快照.json` 一致）。
**优先级**：脚本里内联的 `CONFIG.persistent / continuous / actions` **高于**模板，用来做临时覆盖。

## 三、持久类字段（写一次就留住）

| 字段 | 类型 | 说明 / 建议值 |
|---|---|---|
| `statLifeMax` / `statLifeMax2` | int | 生命上限（原版吃满 500；两个一起写，UI 立刻更新） |
| `statLife` | int | 当前生命（别超过上限，会被夹回） |
| `statManaMax` / `statManaMax2` / `statMana` | int | 魔力（原版吃满 200） |
| `difficulty` | **byte** | 0 经典 / 1 中核 / 2 硬核 / 3 旅途 |
| `breath` | int | 水下呼吸 |
| `lavaMax` | int | 岩浆耐受时间 |
| `name` / `hair` / `skinColor` … | string/int | 外观（改名字需 `il2cpp_string_new`，一般不必） |

> `difficulty` 调小只影响之后的死亡处理，**已经掉出去的物品不会回来**。

## 四、每帧持续类字段（必须 Hook）

`Player.ResetEffects()` 每秒执行 60 次，且**对每个角色各调用一次**；这些字段写一次会被立刻覆盖，脚本用 Hook 在 `onLeave` 里对**选中的角色**重写（多目标时只改命中的那几个）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `statDefense` | int | 防御 |
| `meleeDamage` `rangedDamage` `magicDamage` `minionDamage` | float | 伤害倍率（1.0 基准） |
| `meleeCrit` `rangedCrit` `magicCrit` | int | 暴击（4 基准，100 必暴） |
| `meleeSpeed` `pickSpeed` `tileSpeed` `wallSpeed` | float | 攻速 / 采集速度 |
| `moveSpeed` `maxRunSpeed` `accRunSpeed` | float | 移速（别超 ~3，会穿墙） |
| `jumpSpeedBoost` `autoJump` | float/bool | 跳跃 |
| `wingTime` `wingTimeMax` | int | 翅膀（0 = 不能飞） |
| `luck` `endurance` | float | 幸运 / 减伤(0~0.5) |
| `immuneTime` `onHitDodge` `shadowDodge` `lavaImmune` `shimmerImmune` | int/bool | 无敌与抗性 |

## 五、方法调用类（游戏原生，最稳）

| 操作 | 方法 | 参数 |
|---|---|---|
| 治疗 | `Player.Heal(int)` | 点数（-1 表示回满，脚本自动换算） |
| 加增益 | `Player.AddBuff(int type, int time, bool quiet)` | ID 见 `buff_ids.json`；60 帧 = 1 秒 |
| 移除增益 | `Player.DelBuff(int index)` / `ClearBuff(int type)` | 槽位 / ID |
| 传送 | `Player.Teleport(Vector2, int style, int extraInfo)` | 只对第一个目标执行 |
| 生成物品 | `Item.NewItem(X,Y,W,H,Type,Stack,noBroadcast,pfix,noGrabDelay)` | 掉在目标脚下 |
| 屏幕提示 | `Main.NewText(string, Color)` | 2 参 / 4 参 |
| 受伤/死亡 | `Player.Hurt(8参)` / `KillMe(4参)` | **破坏性**，未在脚本里提供 |

## 六、背包操作

`Player.inventory` 是 `Item[59]`（0–49 主背包，50–53 货币，54–58 弹药），每个槽位**一开始就有 Item 实例**，
所以可以直接：取槽位对象 → `Item.SetDefaults(type)` → 写 `Item.stack`。脚本里对应 `actions.toInventory`：
```js
toInventory: [{ slot: 20, type: 4956, stack: 1 }]
```

## 七、典型场景

| 场景 | 做法 |
|---|---|
| **刚建的新角色想直接起飞** | `enabled:true, target:"local", profile:"满配角色"` → 跑一次 |
| **同一个模板给多个角色** | `target:"all"`（联机时全体）或 `target:"name:角色名"` |
| **改前先看一眼** | `enabled:false` 跑一遍：扫描 + 属性回读，不写任何数据 |
| **只想临时改一项** | 不碰模板，直接写内联：`persistent:{difficulty:0}` |
| **换回原样** | 重进存档即可（持久字段随存档保存）；持续字段 unload 脚本就失效 |
| **验证机制没坏** | 写入「当前同值」（如 `luck:0`）再回读，正常即链路通 |

## 八、已验证 / 未验证

**已实测通过（本机 2026-09-17）**：
- ✅ 角色扫描与本地玩家识别（`get_LocalPlayer` 属性链）
- ✅ 目标解析：`local` / `all` / `name:` / `slot:`
- ✅ 模板拉取（HTTP 取 `profiles.json`）与合并优先级
- ✅ 持久字段写入（每目标）——用写回同值验证，数值未变
- ✅ `ResetEffects` Hook 多目标过滤：3 秒命中 181 次（≈60/秒）
- ✅ 方法签名：`Heal/1` `AddBuff/3` `DelBuff/1` `ClearBuff/1` `Teleport/3` `Item.NewItem/9` `Item.SetDefaults/1`

**未实测（用前小范围试）**：
- ⚠️ 联机多人（`target:"all"` 只会改到本机内存里的玩家对象，可能与服务器状态不一致）
- ⚠️ 传送落点可能卡进方块
- ⚠️ 移速 >3、生命 >500 可能触发逻辑异常
- ⚠️ 主菜单下（未进世界）没有活跃角色，脚本会明确提示并退出

## 九、风险

1. **中核/硬核难度**：`difficulty=1/2` 时死亡掉物品，改属性不会阻止掉落逻辑；先 `difficulty:0` 或存箱子。
2. **备份存档**：`/sdcard/Android/data/com.xd.terraria/`（旧存档 `OldSaves/`）——设备 shell(root) 可读写，容器不可。
3. **联机**：本地内存修改只影响本机表现，建议单机使用。
4. **别 unload**：持续类字段依赖 Hook，unload 后立刻回原值。
5. **偏移会变**：附录偏移只对当前版本有效，脚本一律用**字段名**查，不硬编码偏移。
