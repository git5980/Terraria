## 1. il2cpp 反射入口（这一段是踩坑换来的，直接照抄）

### 1.1 导出的解析

```js
var m = Process.findModuleByName('libil2cpp.so');
function NF(name, ret, args){
  var q = null;
  try { q = m.findExportByName(name); } catch(e) {}
  return q === null ? null : new NativeFunction(q, ret, args);
}
```

### 1.2 ⚠️ 踩坑：不要用 `il2cpp_domain_get_assemblies` 去遍历

它的签名是 `const Il2CppAssembly** il2cpp_domain_get_assemblies(domain, size_t* size)`。
**返回的是「指针数组的地址」**，正确读法是：

```js
var arr = il2cpp_domain_get_assemblies(domain, sizePtr);   // Il2CppAssembly**
var asm = arr.add(i * 8).readPointer();                    // 第 i 个 assembly
```

如果像下面这样多解引用一层，就会把 **assembly 当成 image** 传给
`il2cpp_class_from_name`，报出来的却是一个极具误导性的错误：

```js
// ❌ 错误写法
var dp  = arr.readPointer();          // 这一步拿到的是 arr[0]，即第一个 assembly
var asm = dp.add(i*8).readPointer();  // 把 assembly 当数组读 → 读到 token / 元数据
// 结果：Error: access violation accessing 0x5f7465670032c8
//       0x5f746567... 其实是元数据里的 UTF-8 字符串内容（"get_..."），不是合法指针
```

### 1.3 ✅ 推荐入口：直接按名字打开程序集

最稳、最短、不依赖遍历顺序：

```js
var domain_get        = NF('il2cpp_domain_get', 'pointer', []);
var assembly_open     = NF('il2cpp_domain_assembly_open', 'pointer', ['pointer','pointer']);
var assembly_get_image= NF('il2cpp_assembly_get_image', 'pointer', ['pointer']);
var image_get_name    = NF('il2cpp_image_get_name', 'pointer', ['pointer']);

var domain = domain_get();
var img = assembly_get_image(assembly_open(domain, Memory.allocUtf8String('Assembly-CSharp')));
// img → 0xb4000077f6ba0000，image_get_name(img) → "Assembly-CSharp.dll"
```

### 1.4 取类、取字段

```js
var class_from_name           = NF('il2cpp_class_from_name', 'pointer', ['pointer','pointer','pointer']);
var class_get_field_from_name = NF('il2cpp_class_get_field_from_name', 'pointer', ['pointer','pointer']);
var field_get_offset          = NF('il2cpp_field_get_offset', 'int', ['pointer']);
var field_static_get_value    = NF('il2cpp_field_static_get_value', 'void', ['pointer','pointer']);
var class_get_name            = NF('il2cpp_class_get_name', 'pointer', ['pointer']);

var cls  = class_from_name(img, Memory.allocUtf8String('Terraria'), Memory.allocUtf8String('Main'));
var fld  = class_get_field_from_name(cls, Memory.allocUtf8String('player'));
var off  = field_get_offset(fld);            // 1640（静态字段）
var out  = Memory.alloc(16);
field_static_get_value(fld, out);
var arr  = out.readPointer();                // Item[] / Player[] 数组对象
```

### 1.5 ⚠️ NativeFunction 参数个数必须严格一致

`il2cpp_class_get_name` / `il2cpp_field_get_name` / `il2cpp_field_get_offset`
**只接受 1 个参数**（类或字段指针），不要习惯性补一个 `0`，否则
`bad argument count`。`il2cpp_domain_get` 无参数。

### 1.6 il2cpp 数组的内存布局

```
+0x00  klass
+0x08  monitor
+0x10  bounds（通常为 null）
+0x18  length  ← int32，注意别当指针读
+0x20  elements ← 从这里开始，每个元素 8 字节（引用类型）
```

### 1.7 ⚠️ 脚本崩溃会吞掉日志

如果脚本在 `console.log` 之后触发访问违规而挂掉，**缓冲区里的日志可能全部丢失**。
排查时务必：**每步都 `console.log` + 所有解引用都包 `try/catch` + 先校验地址合理性**
（`ptr.toInt32() > 65536` 才继续解引用）。`il2cpp_runtime_invoke` 尤其危险，
参数构造错误会直接打死脚本线程；本次全程未使用它。

## 2. `Terraria.Item` 字段偏移（实测，非猜测）

用 `il2cpp_class_get_fields(cls, &iter)` 迭代出来的**真实**布局：

| 字段 | 偏移 | 说明 |
| --- | --- | --- |
| `type` | **76** | 物品 ID，0 = 空 |
| `stack` | **96** | 数量 |
| `maxStack` | 100 | |
| `damage` | **132** | 伤害 |
| `ammo` | **256** | 本物品**作为弹药**时的 AmmoID |
| `notAmmo` | 260 | |
| `useAmmo` | **264** | 本物品**作为武器**时需要的 AmmoID |
| `prefix` | **344** | ⚠️ **单字节**（byte），不是 int |
| `melee` | 345 | bool |
| `magic` | 346 | bool |
| `ranged` | **347** | bool |
| `value` | 288 | |

> **陷阱**：`prefix@344` 是单字节，紧邻 `melee@345 / magic@346 / ranged@347`。
> 若按 4 字节 `readS32()` 读，会得到 `0x01000000` = `16777216` 这种假值——
> 其中最高字节 `0x01` 其实就是 `ranged=1`。本次一开始就被这个坑到，一度以为
> 所有枪的 prefix 都是 16777216。

### 玩家与背包

```js
// Terraria.Main.player （静态，偏移 1640）→ Player[]，length=256，元素 +0x20
// Player.inventory   （实例，偏移 1256）→ Item[]，length=59
//   0-49  主背包（10 列 × 5 行）
//   50-53 钱币槽
//   54-57 弹药槽
//   58    垃圾桶
```

取当前玩家：
```js
var staticOut = Memory.alloc(16);
field_static_get_value(class_get_field_from_name(clsMain, S('player')), staticOut);
var p0 = staticOut.readPointer().add(0x20).readPointer();   // Player[0]
var inv = p0.add(1256).readPointer();                        // Item[]
var len = inv.add(0x18).readS32();                           // 59
var el  = inv.add(0x20);
```

## 3. 物品**中文名**读取（本次新打通）

`Terraria.Lang` 的静态字段 `_itemNameCache`（**静态偏移 96**）名字像字典，
**实际是 `LocalizedText[]` 数组**：按 `+0x18` 读长度得 **6266**，**索引就是物品 ID**。

```js
var o = Memory.alloc(32);
field_static_get_value(class_get_field_from_name(clsLang, S('_itemNameCache')), o);
var names = o.readPointer();          // LocalizedText[]
var len   = names.add(0x18).readS32();// 6266
var el    = names.add(0x20);

function nameOf(id){
  var lt = el.add(id * 8).readPointer();      // LocalizedText*
  var sp = lt.add(0x18).readPointer();        // +0x10=Key("ItemName.X")，+0x18=本地化值
  var n  = sp.add(0x10).readS32();            // Il2CppString.length
  return sp.add(0x14).readUtf16String(n);     // chars（UTF-16）
}
```

`LocalizedText` 布局：`+0x10` = Key（如 `ItemName.Minishark`），**`+0x18` = 本地化字符串**。

实测样例：

| ID | 名字 |

| 9 | 木材 |
| 23 | 凝胶 |
| 71/72/73/74 | 铜币 / 银币 / 金币 / 铂金币 |
| 95 | 燧发枪 |

## 4. AmmoID 语义（关键结论）

`useAmmo` / `ammo` 存的是 **AmmoID**，而 **AmmoID 的数值恰好等于该类"基础弹药"的物品 ID**。
因此可以直接用 `nameOf(useAmmo)` 反查"这把枪要什么弹药"：

| AmmoID | 对应基础弹药 | 谁在用 |
| --- | --- | --- |
| 97 | 火枪子弹 | 绝大多数枪 |
| 71 | 铜币（硬币类） | 钱币枪 |
| 23 | 凝胶 | 火焰喷射器类 |
| 75 | 坠落之星 | 星星炮 / 超级星星枪炮 |
| 169 | 沙块 | 沙枪 |
| 283 | 种子 | 飞镖手枪 / 飞镖步枪 |
| 771 | 初级火箭 | 雪人炮 / 喜庆礼炮Mk2 |
| 780 | 绿溶液 | 环境改造枪 |
| 931 | 照明弹 | 信号枪 |
| 949 | 雪球 | 雪球炮 |
| 3108 | 钉子 | 钉枪 |

判定"某武器有没有弹药"：

```js
// 先收集背包中所有弹药物品的 ammo 值
var have = {};
for (每个非空槽) { if (item.ammo > 0) have[item.ammo] = 1; }
// 武器无弹药 ⇔ useAmmo > 0 && !have[useAmmo]
```

## 7. JsHook MCP 桥的配置（便于日后重建）

DSH 容器与设备共享 loopback，**不需要 adb forward**：

```yaml
- id: jshook-mcp
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    transport: streamable-http
    serverName: jshook
    url: 'http://127.0.0.1:19820/mcp'
    headers:
      X-Api-Key: '<JsHook 里显示的 key>'
    failOnStartupError: false     # JsHook 没开也不要拖垮 Web 启动
```

工具以 `mcp__jshook__<原名>` 暴露。若需要收窄范围，可在 `agent/created`
监听器里对该 agent 作用域调用 `tools.restrict({ deny: [...] })`
（`restrict` 只作用于单个 agent 作用域，且 MCP 尚未连上时会抛"工具名未注册"，
需捕获后跳过、下次再试）。

**验证桥是否活着**：
```bash
curl -s -m 3 -o /dev/null -w '%{http_code}\n' http://127.0.0.1:19820/mcp   # 无 key → 401
```

**注意**：`frida_execute` 每次执行前需要先 `frida_unload`（同一时刻只允许一个脚本），
而 unload **不会撤销已安装的 Hook**（`Interceptor.attach` 等仍在），要彻底清干净
必须重启目标应用。
